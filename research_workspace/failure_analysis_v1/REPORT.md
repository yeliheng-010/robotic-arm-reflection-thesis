# 三组物理闭环失败归因与补采依据

结论：先补有物理验证的决策覆盖和多步恢复证据，再考虑训练。180/180任务重新通过原物理、噪声、候选与模型双日志审计；12次方法任务失败集中在5个开发条件。此次分析未重跑物理任务、未创建训练样本、未使用最终测试。

## 已验证结果

规则57/60，基础4B55/60，微调4B56/60；每组144次尝试。60条件共享6个批次内种子组，不是60个独立随机种子。微调新增成功仅1个，不支持稳定优于基础或规则的结论。

基础与微调共84对决策位置，其中83对原选择器messages完全相同：75对选同一动作，8对不同。另1对由于历史状态已分叉，输入不同，不能作为同输入动作比较。

8次同输入差异中，7次基础选下降−90°、微调选−45°：6次两者均成功，1次只有−45°成功。剩余1次是残差缺失时基础调抓取深度、微调减速，两者最终都失败。因此当前改善主要表现为一个下降姿态选择案例，不能据此声称已经学会一般多步反思。

## 159条训练监督的覆盖

| 成功标签动作 | 数量 |
|---|---:|
| 抓取残差补偿 | 30 |
| 放置残差补偿 | 44 |
| 抬升 | 64 |
| 下降−45° | 21 |
| 切换抓取候选、调整深度、减速、下降−90° | 各0 |

只有10条标签输入不含任何可见XY残差，全部是抬升；并没有覆盖“抓取残差缺失时如何探索”的成功监督。所有下降标签均为−45°，与当前选择偏好一致，但尚不能由统计直接证明偏好的唯一成因。

`data_review_v1/extract.py` 仅保留下一次尝试**整体成功**的决策；修复抓取后仍撞挡板、换候选后下一次仍失败但后来可成功等步骤，未作为成功标签保留。这是原保守筛选的明确边界，不是损坏数据。原先排除的多成功标签也不能视为坏标签。

## 下一步已设计

独立 `targeted_collection_v1`：24个新训练条件、6个新种子、两物体对、两复合故障、六档反馈噪声。规则轨迹的每个决策节点最多比较两种其他语义候选，后续沿用规则，整条轨迹仍最多3次。最多240次新增物理执行，先4条件冒烟再其余20条件。

记录完全相同输入下的已观察成功动作集合，保留立即成功、经后续恢复成功、失败、多解、矛盾与旧开发输入重合。该数据来源为规则候选分支搜索，model=null，不伪称教师模型生成；不是新的模型性能对照。有限分支不等于完整oracle，规则后续策略也会影响结果。

本轮不直接把中间阶段推进视作成功，不改此前180任务的三次预算，不把开发任务复制进训练，不自动追加epoch。新试采最终审计后再判断可用监督数量与是否需要多标签目标。

证据：`summary.json`、`cases.json`、`source_hashes.json`、只读审计脚本`analyze.py`。服务器审计作业5120；首个提交因分区名gpu不合法被拒，未创建作业，改用仓库既有batch分区后执行。
