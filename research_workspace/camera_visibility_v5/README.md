# 轻遮挡相机入口

此版本只处理新的 `varied_noisy` 场景。`baseline`、旧数据、旧模型和原始场景配置不改。工程目录v1至v5是修订记录，不是新增场景档位。

## 新的规则

检查14个桌面实例：3容器、4几何物体，以及Apple/Banana/Hammer/Knife/Duck/Flashlight/rubik七个固定背景物件。每实例须同时满足：

- 同视角隔离轮廓的可见比例≥85%（最多15%遮挡）；
- 可见像素≥576、可见包围框短边≥16像素（640×640图像）；
- 最大连通分量≥可见像素80%；
- 完整几何投影距图像边缘≥24像素；
- 保留原6 mm深度一致性检查。

相机仍在原方位±60°、仰角35–75°、距离基准0.8–1.3倍和FOV48–65°内取样。原视角优先，其后按固定种子提案，最多256个，取首个合格视角。预算耗尽即拒绝，不使用旧相机兜底，不依照抓取成功筛选。布局、配色、3 mm/2%噪声参数不改。

## 新采集接线

在旧的几何/任务资格检查之前，对每个新增强配置调用：

```python
from cv_select import select, check_observation
from cv_entry import approved_config

updated, selection = select(original_config, selection_folder)
# 被拒绝时应留账并跳过，不把None替换回original_config。
if updated is not None:
    config = approved_config(selection_folder, original_config)
    # 用config重新渲染并运行原几何/任务资格检查。
```

`approved_config`会重新核验全部实例门槛、深度检查以及布局/配色/噪声未变，并核验读取的相机与所选相机相同。选出清晰视角不代表抓取可行，不能跳过原几何资格。

若机器人运动后继续向模型提供图像，须在该暂停状态调用 `check_observation(env, renderer, config['camera'])`；该入口不达标即抛错，不会把模糊/严重遮挡画面当正常观测。此次验证仅覆盖初态视角，没有把新检查插入旧冻结训练或旧闭环进程。可见性私有统计用于场景资格和审计，不作为模型根因标签。

## 核验范围

`run.sbatch`只检查三个既有开发布局，不执行抓取或模型调用。前64个旧候选仅在初始测量严格相同、RGB仅有稀疏量化差的情况下复用；之后继续到256。新调用不传prior时，从原视角完整搜索。

独立 `audit.sbatch`须设置 `CV_RUN_JOB` 并依赖run成功，重新创建场景，核验全部14物体测量逐值相等、RGB一致性与非相机配置不变。RGB只允许≤2/255色阶、≤0.1%像素变化；这是6303实际诊断出的跨进程微小渲染差异，未放宽任何遮挡/物理门槛。大面积或更大色差仍失败。

面积与轮廓规则是可辨认性的工程代理，需要查看真实截图；尚不能宣称模型识别率或任务成功率已经提高。背景物件位置仍未随机化。
