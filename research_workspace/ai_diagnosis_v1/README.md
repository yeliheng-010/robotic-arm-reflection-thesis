# AI自主诊断：审查与离线接口原型

本轮将后续研究方向改为“AI基于允许的观测分析失败并选择修正”。已完成信息流审查、输入隔离和提议校验；**尚未接通实际感知、模型调用或物理执行，不是已验证的AI闭环**。

- [现有实现审查](AUDIT.md)：当前两场景入口没有模型调用；旧模型菜单、理想标签和合成补看协议的限制。
- [具体协议与下一阶段门禁](PROTOCOL.md)：三方法共享输入/动作/预算，AI提出假设，评估真值隔离，保持两个场景。
- [离线核对结果](OFFLINE_VERIFICATION.json)：21份源文件身份未变，2条真实耗尽账本仅STOP，模型/物理/训练调用均0。
- [测试记录](green-final.log)：18项通过；[红灯记录](red.log)保留最初隐藏信息穿透与非法动作未拒绝的复现。

`boundary.py`只构造命令与感知候选数量的白名单，不透传原始错误、诊断、真值和文件路径。`prompts.py`生成直接决策/诊断决策提示，双方用户输入相同。`decision.py`和`action_check.py`仅校验模型提议，不代选也不执行。能力默认不登记，实际接线通过后才能开放。

真实样例位于`examples/`。它们没有附加RGB/深度/机器人时序，也没有AI回复，只用于验证信息隔离和三次预算；不能据此评价模型是否会分析掉落。允许“未知”，不把解析通过或引用存在等同于归因正确。
