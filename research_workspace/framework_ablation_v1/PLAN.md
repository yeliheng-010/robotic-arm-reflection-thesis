# 四组框架消融与预算对照 Implementation Plan

**Goal:** 在服务器无人值守完成四组开发集对照，区分重试、反馈规则和模型历史信息的作用。
**Architecture:** 新目录独立冻结，复用原物理执行/资格/噪声审计。四组 retry/rule/current/history；候选生成一律不读取历史。模型两组均禁用 adapter，使用相同基础4B。预算3为主实验，预算4为独立敏感性分析。
**Tech Stack:** Python、MuJoCo、Qwen3.5-4B、现有量化推理环境、Slurm。

## 执行任务
- [x] 实现独立策略与审计：retry原参数重试；rule固定规则；current仅当前反馈；history额外读决策历史。
- [x] 测试历史隔离、相同候选、模型身份、策略审计、预算与恢复、服务退出。5175预检29项通过。
- [x] 冻结60开发条件×4方法×2预算=480条；资格不重采，最终测试不读取。27份执行源文件本地/服务器hash一致。
- [x] CPU预检→基础模型服务验收→12条件×4方法冒烟48条→审计/篡改门禁。20项真实记录篡改拒绝通过。
- [x] 主实验240条（复用48）→主实验审计→预算4的240条→最终审计。480/480完成；240条预算前缀通过。
- [x] 汇总各预算、任务类型、种子组与方法的结果、配对差异和恢复成本，生成明早验收报告。12份结果文件本地/服务器hash一致。

## 公平性与边界
最多1680次物理执行（720+960），不含既有资格记录；不搜索额外动作、不隐藏重试、不改成功判据。数值噪声和缺失保留。任务的阶段/接触信息仍为理想信息；只可声称仿真开发集结果。60条件共享6个批次内种子组，不当成60独立种子。当前状态与尝试编号允许可见；候选不通过历史过滤。完整组的历史由错误、修正前状态、实际选中动作组成；不额外增加自由文本思维链。

主实验无历史候选生成与旧版本不同，旧55/60等仅作背景，不复用旧结果。单步与完整组只改变history字段；沿用同一系统提示。retry不调用候选/模型，只看成功终止信号；它是保持参数的重复执行基线，不代表全部无反馈探索策略。

预算4必须与预算3已有尝试前缀一致（物理允许既定浮点容差），前三次决策输入与选择可核验；额外预算不计为模型改进。报告显式区分主实验/补充实验。只有工程与审计通过才进入下一阶段，不以成功率高低为门禁。

## 无人值守与验收
GPU仅由Slurm分配：一张基础模型服务，最多三张仿真分片，每片两个隔离worker。协调器运行在服务作业内，所有文件保存在服务器。任一阶段失败/超时/服务退出即停止后继阶段，保留失败现场，仅取消本轮自己提交且仍活动的作业，停止本轮服务子进程。无自动重复试验。每阶段报告和总状态原子写入；断开浏览器和关闭本地电脑不影响已提交Slurm作业。

新观测机制、训练补采、新微调及最终盲测不混入本轮；它们需要根据对照结果进一步设计。
