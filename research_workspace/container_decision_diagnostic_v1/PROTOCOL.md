# 容器随机布局失败诊断 v1

## 目的与边界

解释既有规则5/11、基础4B模型1/11的恢复差距，覆盖全部11个初始失败。
本轮是事后开发诊断，不是独立泛化评测；无训练、无最终盲测、无新反馈噪声。
冻结旧实验，不改旧源码和结果，不采用额外模型调用挑选有利输出。

## 模型选择实验

冻结11个第二次失败快照（已有一次measured_grasp修正）和原请求。
基础Qwen3.5-4B，NF4/FP16，adapter禁用，温度0、种子42、max_tokens128。
启动先回放旧开发输入0、52。随后每个快照四种输入，共44次任务调用：

1. replay：原请求原样回放，文本和动作必须精确复现。
2. reverse：只倒序candidates及legal_action_ids，状态、历史和反馈不变。
3. summary：追加已执行补偿仍失败及阶段提醒，不给未来成功标签。
4. expert_hint：追加优先下一个未用抓取候选的专家启发式，单独标注来源。

无合法输出时计为未成功，不重试、不回退。全部请求先于新物理分支。

## 物理动作覆盖

穷举11快照的67个原合法候选，每个执行一次；保留所有失败。
另对2个carry_transport阶段IK失败，分别测试lift_height=0.20/0.25/0.30米，
其余状态固定为对应第二次失败的状态，共6个专家扩展分支。原值0.35米。
总计73个物理分支。无新抓取姿态、无下降路径变更、无OBSERVE。
每分支重置原布局及种子，并用第三次尝试的语义记录反馈。
原模型/规则选中的动作同时用作22项结果回放，校验成功、错误与阶段。
穷举上界不是部署策略，不得换算为新的完整闭环成功率。

## 执行与验收

CPU源数据预检、单元测试、冻结 → 单卡模型 → 模型审计 → 四卡4分支冒烟
→ 冒烟审计 → 四卡剩余69分支 → 最终审计、analysis.json、REPORT.md。
冒烟覆盖空抓、碰撞、IK的原规则选择及一个低抬升分支。
所有GPU通过Slurm；控制器脱离本机运行。各阶段失败阻断后继，禁止隐式重跑。
检查原布局、物体及机器人初态、执行器参数、成功判据、请求身份和完整账本。
模型与物理审计均执行篡改拒绝测试。执行前冻结文件；冻结后修复另建版本。

## 解释限制

已有开发结果参与提出假设，不能宣称无偏验证；11例样本不足以支持泛化结论。
专家提示带来收益应归于混合策略；动作均失败不证明场景不可解。
每个案例多分支相关，不能当作73个独立任务报告显著性。
