# 189输入模型的四组开发闭环

目标：在既定60个开发条件和每任务最多3次尝试下，比较rule、base、previous159、new189的真实仿真成功及配对差异。用户已批准此阶段，不追加训练轮次，不使用最终测试。

共240任务、最多720次物理执行。第二批20条件＋第三批40条件，沿用原资格记录、初态、候选、反馈噪声与持续故障；所有分母保留，失败不换种子。60条件共享6个批次内种子组，不称60个独立种子。开发场景已用于迭代，不能当最终盲测。

新目录set_closed_loop_v1复用已验证闭环组件，旧目录只读。本轮四组全部重新执行，避免把历史对照当作本轮运行。固定原12个冒烟条件，每条件四组共48任务，审计后复用到240总分母。

单卡加载同一NF4/FP16基础4B及两个独立adapter；HTTP服务串行切换，基础模型禁用adapter。每请求身份、实际adapter及服务端双日志审计；原159与新189分别对保存logits重载验证，并进行交替切换的离线文本回放。greedy、128token、无thinking完全一致。无隐藏请求重试、无规则兜底，非法选择计结果；服务错误阻止扩跑。

三卡仿真分片各最多2个隔离worker，一卡推理；全部Slurm。服务最终审计后停止，冒烟/提交失败要保留记录并释放本轮服务。其他用户作业不干预。

验证：四组方法及adapter切换的先失败后通过测试、既有边界和EOS测试、冻结身份与资格复核、GPU重载和交替回放、48任务冒烟、真实记录篡改拒绝、跨方法初态/相同状态物理/候选噪声审计、完整240任务配对统计。主比较previous159与new189，附基础/规则比较。训练数据量、目标聚合和步数同时变化，不作单因素归因。
