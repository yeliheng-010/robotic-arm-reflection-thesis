# 轻遮挡相机筛选实施计划

目标：保持两场景和现有布局/配色/噪声，只改变新版本相机筛选，全部14个桌面实例均有清晰可见部分。当前随机移动7实例，另7个固定背景实例也参与可见性检查。

原因：旧natural_top_preflight只检查source/destination的70%/64像素，964294绿色圆柱仅8像素仍能进入任务。完整入画也不等于无遮挡。

规则：每实例可见面积/同视角单独渲染面积≥85%，可见像素≥576，包围框短边≥16像素，最大连通分量≥可见像素80%，完整几何投影距边≥24像素。维持原35–75度仰角、±60度方位、48–65度FOV及0.8–1.3基准距离；原视点优先，最多256候选，首个全部达标视点才接受。不能靠放宽标准补足数量。纯可见性与尺寸门槛不等同语义识别保证，需要实际截图审阅。

修订依据：v1测量存在轮廓外分割像素，v2以真实隔离轮廓交集修正，10测试通过。v2的6300三个布局各64候选均拒绝：964306候选54可见性通过，但6.227mm深度检查超过原6mm门槛；其余布局仍有轮廓遮挡或小物件像素不足。v3不放宽任何门槛，仅扩大候选预算256；前三布局前64候选与原始预览哈希核对后复用，不重跑搬运或训练。

范围：新增policy.py、metrics.py、selector.py、run.py及独立Slurm入口；只对三个既有开发布局964103/964294/964306重渲染，不执行抓取、不训练、不改旧配置或权重。保存新旧图像、逐实例指标、全部候选、有效新配置和拒绝结果。运行时观测检查复用同一门槛；初态通过不保证机器人运动后仍通过。

步骤：
- [ ] 写回归测试并在Slurm确认先失败。
- [ ] 实现全部实例的严格门槛及确定性选择，测试通过。
- [ ] Slurm执行三个布局的实际渲染，核对不改布局、旧图、相机标定及新截图。
- [ ] 自审、记录范围与限制，提供后续新采集使用入口；不自动重跑完整采集。

技能：systematic-debugging、writing-plans（按项目规则采用短计划）、test-driven-development、verification-before-completion、requesting-code-review清单自审。用户限定的子代理型号不可用，因此不冒充独立代理审查。
