# 后续路线与验收条件

更新：2026-10-28。当前顺序是**诊断已完成 → 根据证据修复 → 有针对性地扩量/训练 → 独立评估**。不把“凑够固定训练条数”作为所有后续工作的前置条件。

## 1. 已完成：观测决策诊断

402任务请求、66分支/物理执行均完成，最终审计通过，详见[进度快照](CURRENT_PROGRESS.md)。验收口径：

- 全部计划请求、11来源快照、物理分支均有明确状态，无遗漏或静默重试。
- 原请求回放、身份、费用、预算、输入/动作、物理结果和账本核对。
- 按提示变体、历史组、缺测条件、观测次数、选择器及种子组报告全部结果。
- 工程门禁通过且最终报告生成；低成功率也是应保留的有效实验结果。

## 2. 根据诊断决定修复，而不是预设结论

| 观察到的结果 | 下一步 |
|---|---|
| 完整动作表示改变了选择 | 新版统一接口，在独立开发条件验证；不追写原结果 |
| 表示改变无效，但明确指令改变行为 | 检查指令是否过度触发、是否提高物理成功及费用；区分策略注入与自主决策 |
| 能理解费用，却不会合理分配观测 | 设计观测价值/时机监督，保留真实执行后果 |
| 更多观测没有稳定物理收益 | 先改观测与场景设计，检查噪声、候选及控制器的限制 |
| 规则持续足以解决任务 | 将贡献定位于反馈与观测机制；如研究模型优势，需预先设计更有区分度的任务 |

当前结果显示“补全候选条目仍不观察、明确指令后全部观察”。固定补看0/1/2次后，规则成功0/5/6，模型1/6/7，分母各11。这支持信息增量的价值，但明确指令的自主闭环策略仍待评估。下一步先冻结触发规则，在需要与不需要观测的独立条件上比较效果和费用，再决定是否训练；本次未启动新作业。

## 3. 再做有针对性的数据集与微调

扩量应覆盖不同失败阶段、测量质量、观测预算和可恢复性，同时保留无需观测、观测无收益、错误修正等负例。按场景与种子隔离开发/训练/最终测试。

监督来源逐条标记：程序规则、Flash教师、实验干预或执行验证。成功动作集合只包含已验证成员，不将集合外动作全部判成失败。

训练前冻结比较：基础4B、旧adapter、新adapter、强规则；尽量一次只改变数据规模、目标或epoch之一。若小规模已有稳定收益，再扩展；若无收益，保留结果并解释边界。

## 4. 冻结版本，开展独立评估

- 同条件配对比较系统成功与恢复率，报告全部失败和成本。
- 分开消融反馈质量、聚合、主动观测、历史及微调。
- 使用未参与调参的种子和任务组合，防止同源快照重复计数。
- 预先确定实验单位和统计方法，按种子组处理相关性。
- 完成开发选择后才使用最终盲测。

最终实验规模应由条件覆盖、有效独立重复与资源预算确定，不用更多相关轨迹代替独立样本。
