# 后续路线、资源安排与论文组织

对应论文题目：《基于机械臂的错误反馈于智能反思系统》（作者原文）。路线按错误反馈、反思决策与系统闭环组织，微调是其中一个环节。

## 1. 优先级

当前最高优先级是完成数据扩量与审计、建立新冻结评估版本、验证独立任务上的实际收益。增加epoch、更换更大模型、多模态训练均以独立评估的瓶颈为依据。

| 阶段 | 工作 | 交付与验收 | 预估时间性质 |
|---|---|---|---|
| M0：当前成果归档 | 保存计划、机器结果、开发对照、截图、来源说明 | 本仓库；数字与原始结果可对应 | 本轮完成 |
| M1：扩量与审计 | 继续双卡采集，到门槛后正常收尾，冻结新版数据 | ≥1000/100/100、训练每类≥100；来源/隔离/物理审计通过 | 采集约11～14小时量级，另留半天审核与问题处理 |
| M2：运行版本验收 | 整合零调用安全汇总，新目录冻结，四类端到端smoke | 首轮成功、合法修正、非法输出、服务失败均可追踪 | 约半天至1天工程预算 |
| M3：新版SFT与选择 | 1epoch起步，数据量曲线，必要时2/3epoch，验证集选参 | 固定数据hash、checkpoint、真实更新、独立重载、验证闭环 | 约1～2天含开发评估，不代表GPU持续训练时长 |
| M4：主比较与泛化 | 冻结最终任务，四组同预算；新任务族/扰动分层 | 完整任务分母、效应量与区间、失败分析 | 起始约2～4天，先实测吞吐再修正 |
| M5：消融与重复性补足 | 证据消融、训练seed、必要的等预算对照 | 至少一套解释收益来源的实验，负结果完整保留 | 约2～4天，受M3/M4结果影响 |
| M6：论文整理 | 方法、实验、局限、文献定位、图表与复现材料 | 结论不越过证据，导师讨论后定稿 | 与M2—M5并行，非承诺提交日期 |

上述为工作预算，不是执行完成时间承诺；受共享GPU调度、样本产率、任务族覆盖和失败修复影响。独立评估往往比一次QLoRA训练更耗时。

## 3. 双卡与四卡资源安排

当前双卡先保证采集；训练或评估需要GPU时，通过正常收尾减少一个采集lane，采用一卡采集、另卡训练/模型推理与仿真评估的已验收方案。显存、CPU和进程隔离以实际smoke为准，不直接推定所有组合可并发。

若管理员释放全部调度配额，先做四卡隔离与输出一致性smoke，再考虑两卡采集、一卡训练、一卡评估。不要在未验证收益前引入四卡DDP；4B QLoRA已能单卡运行，当前瓶颈更可能是独立场景与仿真吞吐。

保留作业ID、部署目录与资源映射。不得覆盖CUDA_VISIBLE_DEVICES或取消非本任务服务。后台任务由Slurm维持，本地电脑关闭不等于作业停止。

## 4. 结果驱动的分支

| 观察到的结果 | 下一步 | 论文解释 |
|---|---|---|
| SFT优于base，和rule持平 | 看新扰动/新族与成本；保留规则强基线 | 规则知识可蒸馏，不声称优于教师 |
| 验证loss极低，独立闭环无改善 | 检查证据输入、标签模板、选择偏差与近重复 | 标签模仿与任务能力存在差距 |
| 同族有效，OOD下降明显 | 增加训练任务族、幅度档位与失败样式 | 泛化受限，不能靠重复种子隐藏 |
| 多数失败发生在无候选/IK | 单独修几何或规划并重新冻结 | 反思参数不能解决上游不可执行性 |
| 增加epoch后性能下降 | 选较早checkpoint，补数据多样性 | 过拟合，不继续机械堆轮次 |
| rule全面更好且成本低 | 保留rule作为部署方案；分析模型失败 | 负结果同样可报告，收缩方法主张 |
| 服务/汇总异常增加 | 暂停新批次、保留日志、先验收运行链路 | 不能将基础设施异常混成模型优劣 |

## 5. 长期发展：有条件扩展

### A. 从规则模板模仿到多样化监督

规则蒸馏先证明可执行修正学习。进一步引入强模型、人工核验或混合选择时，保留独立数据来源与成本记录。比较等样本量、等任务覆盖下的rule-only与hybrid，避免同时改变数据量和来源。

对于规则没有覆盖的新故障，先建立失败判据与可执行动作范围，再采样；不能只添加长解释文本就称为更强推理。

### B. 从仿真感知到真实视觉输入

先固定反思器，对比simulation感知与VLM/SAM链路，定位识别、分割、几何、执行、反思各阶段损失；再决定是否让反思器接收图像。图像训练需要单独的数据版本、可用视觉模型端点和显存验收。

如果题目必须包含视觉语言模型，本层至少应提供真实视觉链路的闭环对照；当前文本修正训练不能替代这部分证据。

### C. 从仿真到真实机器人

前提为可用机械臂、相机标定、碰撞安全限制与人工监护条件。先小范围可控任务，独立报告真机数据，区分sim-to-real偏差。当前没有真实机械臂测试证据，不把真机验证写为已完成或必然可交付。

## 6. 论文章节建议

| 章节 | 核心内容 | 当前可用 | 后续需补 |
|---|---|---|---|
| 绪论 | 失败恢复问题、任务边界、研究问题 | 作者提供的题目与项目问题定义 | 导师开题要求、相关工作核验与差异 |
| 系统与错误反馈 | 仿真、感知、抓取、错误状态、反馈字段、验收 | 现有流程与轨迹 | 统一图示、坐标系、反馈质量审计 |
| 反馈驱动的数据构建 | 规则来源、配对重试、过滤、去重、分组 | 采集与审计实现 | 最终分布、泄漏审计报告 |
| 智能反思方法 | 反馈到修正的决策、输出约束、输入模板、QLoRA | 规则/base/SFT及pilot设置 | 学习曲线、模型选择、证据消融与重复seed |
| 实验结果 | 四组主比较、消融、泛化、效率、失败案例 | 6场景开发对照 | 封存主实验、区间、负结果 |
| 总结与展望 | 已证实内容、规则依赖、仿真真值限制 | 当前边界清楚 | 根据实际结果更新，不预写成功结论 |

建议图表：系统闭环图；数据来源与过滤流程；任务族和故障分布；数据量学习曲线；四组成功率与区间；证据消融；OOD分层；收益与失败案例；成本表。

文献调研应覆盖机器人失败恢复、语言模型反馈/反思、规则或执行验证监督、参数高效微调和具身评估。逐篇记录任务、输入、监督来源、基线、分母与泛化设置，不用未核验引用支持“首创”。

## 7. 最小论文实验闭环

最低可交付应包括：一份可审计的数据快照；一个冻结训练配置；四组同预算完整任务比较；至少一个解释收益来源的消融；至少一种未见条件评估；失败与局限分析。若独立结果不支持改进，应保留负结果并与导师调整研究主张，而不是只保留开发集结果。
