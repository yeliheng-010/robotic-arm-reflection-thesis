更新日期：2026-11-19（America/Los_Angeles）。本页基于已保存的服务器结果、历史实验图片和代码整理；本次更新没有重新运行实验、调用模型或训练。

**目前已验证完整抓取—搬运—放置—回程能够成功执行，但还没有得到大规模成功率结论。** 单次作业6891成功1/1；后续预登记200个条件的批量作业6892实际执行4次，成功3次、工程异常1次，其余196个条件被停止机制跳过。汇总作业6895已经结束。

## 1. 我们正在解决什么问题，现在到了哪一阶段

项目最终研究的是机械臂执行出错后，能否根据可观察证据和错误反馈，选择合理的修正并真正恢复任务。为此，必须先让感知、动作表示、路径检查、物理执行和任务验收接在同一条可追踪的流程中；“模型给出一个合法动作”与“物体实际放进目标容器”是不同的成果。

当前工作已经推进到**完整物理任务执行与固定动作鲁棒性评估**阶段。此前重点是观察资格、感知结果、抓姿和执行入口；现在已经获得完整抓放成功记录，新的阻塞发生在批量运行的持物路径检查入口。当前还不是模型在线自主反思闭环，也没有证据表明微调带来了本轮成功率提升。

## 3. 单次完整抓放具体完成了什么

单次作业**6891**使用最新保存动作，从原完整任务初态开始，依次执行接近、闭合、夹持确认、抬升搬运、释放、稳定等待及回程。Slurm状态为COMPLETED/0:0，用时45秒；同时，任务结果中的success、completed和physical_placement均为true，safety_error为null。

```mermaid
flowchart LR
    A[接近目标] --> B[闭合夹爪]
    B --> C[夹持确认]
    C --> D[抬升与搬运]
    D --> E[释放到目标箱]
    E --> F[稳定等待与回程]
    classDef done fill:#e5f4ec,stroke:#28794b,color:#173c28;
    class A,B,C,D,E,F done;
```

**图3｜6891已经完成的执行流程。** 这是依据阶段记录绘制的流程示意，不是动作录像。物理放置验收同时要求物体位于目标容器的XY/Z范围、有支撑且已稳定；程序正常退出本身不算任务成功。

|6891的关键记录|结果|应如何理解|
|---|---|---|
|完整流程与物理放置|均通过|成功包含释放后的放置及回程，不仅是夹住物体|
|目标箱范围、支撑、稳定|均为true|来自该次运行时仿真评价|
|XY中心残差|约33.86mm|未要求精确落在箱体中心；不能将中心偏差单独等同失败|
|物体倾角|约6.03°|运行记录中的姿态量，不是另一次独立复算|
|初始化步数|500|与实际任务积分单独记账|
|任务步数|8250|原生请求数与返回数一致|
|重试、模型调用、训练|均为0|没有通过多次重试筛选出这次成功|

本次证明的是**这套动作在一个固定条件下可完成任务**。它不证明动作在各种位置上都稳定，也不改变历史静态闭合拒绝或观察资格拒绝的记录；运行时监视器未触发中止，也不等于每个积分时刻均已接受独立接触审计。

## 4. 为什么安排200个条件，实际覆盖了多少

在单次成功之后，本批保持机器人、目标箱、其余场景和保存动作不变，只改变胶囊初始世界坐标XY位置。预登记偏移半径为**1、2、3、5、10mm**，每档40个等角度方向，方向间隔9°，合计200个不同条件。

这样的安排回答一个较小而明确的问题：**同一套动作对目标位置的小幅变化有多敏感？** 它不是200个独立随机布局，也不是让模型在每个新场景里重新观察、规划或反思。此前中心条件6891不重跑，也不并入本批分母。

```mermaid
flowchart TB
    P[预登记200个位置条件] --> A[实际进入任务执行：4个]
    P --> K[STOP后跳过：196个]
    A --> S[完整抓放成功：3个]
    A --> E[工程异常中止：1个]
    S --> R[已执行尝试内成功比例：3/4 = 75%]
    E --> R
    K --> N[未执行，不能计作物理失败]
    classDef success fill:#e5f4ec,stroke:#28794b,color:#173c28;
    classDef failure fill:#fff0df,stroke:#b86220,color:#65340f;
    classDef skipped fill:#eef1f5,stroke:#7a8697,color:#334155;
    class S success;
    class E failure;
    class K,N skipped;
```

**图4｜200个条件的最终去向。** 框的面积不表示比例，具体数量以框中文字为准。四次实际尝试的成功比例为75%，而计划条件的执行覆盖只有4/200＝2%；两者衡量的不是同一件事。200项记录全部齐全，表示每个条件都有结果或跳过去向，不表示完成了200次物理任务。

|---|---:|---:|---:|---:|---:|
|1mm|40|4|3|1|36|

因此，现在可以报告“1mm档最先执行的四个方向中，三次完整成功”，不能报告“五档大规模测试成功率75%”。更不能删除工程异常和未执行条件，只保留三个成功样本来计算100%。

## 5. 具体在哪一步出了问题

|条件|偏移半径|方向|任务步数|最后记录的阶段|结果|
|---|---:|---:|---:|---|---|
|000|1mm|0°|8250|returned_home|完整成功|
|001|1mm|9°|8250|returned_home|完整成功|
|002|1mm|18°|3250|grasp_confirmed|工程异常|
|003|1mm|27°|8250|returned_home|完整成功|

条件002已经完成接近、闭合和夹持确认。随后，在准备执行持物搬运路径时，几何检查需要把物体姿态构造成SE3变换；该入口调用SpatialMath的SE3.Rt时拒绝了传入的旋转矩阵：

```text
runtime.execute
  → GuardedBackend.run
  → hv_geometry.inspect
  → ot_volume.body_pose
  → spatialmath.SE3.Rt
  → ValueError: expecting SO3 or rotation matrix
```

这里的报错表示姿态构造没有通过库的旋转矩阵检查，**目前只能确定失败入口，不能确定数值根因**。现有堆栈不足以证明是正交性误差、数据读取时点、非有限数值或其他原因；也没有证据把它直接归因于碰撞、滑移或模型选择错误。

由于本批将这类错误归为工程异常，程序写入STOP.json，后续条件标记为skipped_batch_stop。每个条件只有一次尝试，没有自动重试。并行度为2，停止标记不会回滚另一项已经开始的任务；不能把条件003的成功理解成对条件002的失败重试。

## 6. 这次结果说明什么，还不能说明什么

**已经得到的进展：** 完整任务链具备真实成功实例；成功判据已经覆盖放置和回程；批量入口能够区分成功、工程异常和未执行条件，并在异常时保留证据、停止扩展执行。研究关注点因此从“是否已经真正执行完整抓放”推进到了“为什么在相邻扰动条件下出现工程异常，以及修复后能覆盖多少条件”。

**仍未完成的部分：** 五档位置扰动扫描只覆盖了2%的计划条件；矩阵异常尚未修复；没有未见布局评估，也没有模型在线反思或微调收益对照。单次6891的1/1与批量3/4各有不同的登记范围，本页分别呈现，不合并为统一性能指标。

本轮新增模型调用、训练和独立事后审计均为0。此前静态闭合检查拒绝、视觉资格拒绝和历史失败记录保持原样，不能因为出现动态成功就把它们改写为通过。

## 7. 接下来应做什么

下一步应围绕已经保存的失败002收敛问题，而不是重新启动一整批重复试验。

1. **先查清失败姿态数据。** 从保存状态及对应读取路径检查有限值、旋转矩阵正交性和行列式，并明确取值时点。先区分数据本身异常、数值容差问题或状态读取时序问题，形成能由证据支持的解释。
2. **针对确认的根因修复。** 在独立新版本做局部修正，保持原碰撞、掉落、释放及任务成功判据；不能通过直接绕过矩阵检查来掩盖异常。
3. **再登记剩余条件的续跑。** 明确哪些是旧未执行的196个条件，哪些属于另行授权的修复验证；已完成条件、旧失败和原claim保留。续跑结果按五档偏移分别报告覆盖、成功和错误类型。

这三项是后续建议，**本次图文更新没有执行诊断、修复或续跑**。完成固定动作的扰动评估后，才有依据进一步讨论跨布局能力和在线反思效果。
