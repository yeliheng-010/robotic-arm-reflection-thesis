# 困难、证据与解决方案

更新：2026-10-28（Asia/Shanghai）。本页区分已验证修复、研究上的解释和仍在检验的假设。数值来源见[证据索引](EVIDENCE_INDEX.md)。

## 1. 监督标签能拟合，物理成功率却提升有限

现象：159 条训练后的开发参考动作匹配从 48/49 到 49/49；但完整 60 条件闭环中，基础模型 55/60，两种微调模型均为 56/60，规则 57/60。

这说明基础模型在当前受限候选任务中已很强。验证 loss 降低和标签匹配提高，不能替代任务成功率。189 输入版本同时改变了数据量、监督集合与更新次数，其结果也不能作为单一数据规模效应。

当前方案：保留训练作为实证比较；暂不以追加 epoch 为默认下一步。先分析可见证据不足、观测预算分配和动作选择错误，再决定训练目标。尚未证明“微调在所有条件下无用”，也未证明“扩大数据一定有效”。

## 2. 单一成功动作标签可能惩罚另一种有效修正

一个失败状态可能有多个可恢复动作。仅以某一规则动作作为唯一标签，容易把不同但可成功的选择判错。

已做：189 输入、197 回复的多成功动作监督版本，完成训练、重载和物理闭环。开发集合命中率与物理指标分别报告。

边界：集合只包含已经观察到的成功动作，未命中不必然失败；集合也不是全动作空间的完备真值。新旧微调在 60 条件均为 56/60，没有出现新增闭环收益。

## 3. 强候选生成器可能让任务过于简单

对观测聚合实验的只读分析中，45/45 次基础模型选择与规则完全一致；每次菜单只有一个测量补偿候选，模型均选中了它。下一次物理成功只有 36/45。

已做：核对完整可见输入、动作 ID 与参数，而不只对比最终成功率；保留全部失败。该分析没有新增模型调用或物理执行，1872 个来源文件未变化。

当前方案：将可测创新放在反馈处理与决策机制上；后续若研究模型决策能力，需要预先设计有信息权衡、阶段变化或候选歧义的条件。不能按看到的失败临时挑选有利案例再冒充独立评估。

## 4. 含噪与缺失反馈下，什么时候应追加观测

已做：最新值/中位数与规则/模型的交叉对照，以及固定首次观测/自适应规则/基础模型/历史模型四组实验。

已有证据：聚合对照中，相同聚合方式的规则与模型成功率一致；主动观测四组中，自适应规则 17/24，另外三组 14/24。三个差异条件都涉及后续失败缺测时的观测预算使用。

未解决：各策略先前行为可能不同，因此不能把成功差异完全归因于同一状态下的观测收益。已完成固定来源快照、0/1/2次观测与固定选择器的66分支对照：11快照中，规则下一步成功0/5/6，模型1/6/7。它支持本批条件的信息增量价值，但实验重置场景后重试一次，不恢复失败瞬间，也不能直接外推自主策略的闭环效果。

## 5. 基础模型没有选择 OBSERVE

现象：最新四组实验的 82 次模型任务调用全部合法，追加观测为 0。历史方案确实收到之前动作/结果，不能归因于没有传历史。

待检验因素：OBSERVE 出现在合法 ID 中，却没有完整候选条目；这可能影响动作显著性，但目前不是已确认根因。

已完成：82 个原请求的四种提示变体、41 个显式成本读取探针、11 个缺测快照的固定观测物理对照。统一候选首/末位用于检验位置影响；显式“缺测先观察”是专家策略注入，其结果只能说明对应指令下的行为，不能包装成自主反思能力。

最新阶段结果：模型402请求及审计已完成。原提示、补全首位和补全末位三个变体各为0/82次选择观测，明确指令组为82/82，费用探针39/41完全正确。物理批量与最终审计也已完成；表示补全在这些变体中未奏效，但不能直接认定根因，也不能将全部选择观测视为策略问题已经解决。状态时间见[当前进度](CURRENT_PROGRESS.md)。

## 6. Flash 模型与训练目标不匹配

本地 Flash-Next 权重曾核验为约 177B 参数的 qwen4exp 架构、约 78 GiB 的 GGUF 推理文件。该信息描述本地部署产物，不替代官方型号和架构说明。当前训练环境未支持这一架构，也没有找到配套可训练 checkpoint。

已采用：保留 Flash 的教师/推理基线角色，使用已具备训练条件的 Qwen3.5-4B 学生模型。训练产物记录学生身份；不能将学生微调写成 Flash 本体微调。

边界：教师输出需要单独保留来源并验证实际后果，不能假设大模型天然提供正确监督。最新主动观测四组比较未使用 Flash，使用基础 4B 且关闭 adapter。

## 7. V100 16GB 的显存与数值限制

训练中曾遇到 OOM/兼容性问题。当前方案使用 NF4/FP16 QLoRA、受控注意力实现、delta-rule FP32 保护、梯度累积等兼容措施。

已验证：159 条版本完成 20 次更新，496 个 adapter 张量变化；峰值分配显存约 13.23 GiB；三个独立重载检查的 logits 差均为 0。189 输入版本也完成训练与重载。具体环境版本见[证据摘要](../evidence/20261028/completed_studies.json)。

边界：这些结果证明对应配置可运行，不能推广为任意长度、模型或依赖版本均可训练。四卡用于任务并行，不代表已经实现四卡分布式训练。

## 8. 成功轨迹的空反馈导致历史构造失败

主动观测 v1 中，成功执行返回 `feedback=None`，旧历史构造仍按失败反馈索引，导致作业失败。

已处理：成功/失败路径分别处理，补充成功轨迹回归与 worker 失败停止检查，在保持 24 条件不变的 v2 中重新执行。v2 最终审计通过。

原失败 v1 的 11 次物理执行、2 次启动回放独立记录；不计入 v2 的性能分母，也不删除以掩盖故障。

## 9. 模型环境意外导入仿真依赖

观测决策诊断 v1 的模型作业 5376，通过 `od_source → am_audit → loopstudy.audit` 导入仅 CPU 仿真审计需要的 spatialmath，模型环境缺少依赖，在加载权重前失败。协调器停止后继，0 模型输出、0 新物理执行。

已处理：将审计依赖移到 CPU inventory 的使用位置，不向模型环境增加不必要依赖。v2 预检 5378 通过 14 项测试；CPU 与模型环境构造的全部 402 个请求完全一致。原失败、回归复现与恢复版本分别保存。

边界：预检通过只说明该导入/输入构造问题已解决，后续模型与物理审计现已通过，完整结果见进度页。

## 10. 后台任务可靠性与资源管理

早期采集曾遇到原生内存累积、Slurm 内存限制，以及显存空闲但 GPU 调度配额被占用的问题。

采用的工程措施：按任务/批次隔离进程，预检、冒烟、批量与最终审计分阶段执行；请求与轨迹对账；任何工程错误停止后继；原结果只读冻结，修复在新版本中运行。资源由 Slurm 分配，管理员处理系统服务和其他用户占位作业。

这些措施改善恢复能力，不等于所有长期内存问题已根治。运行中、队列中、程序退出和最终审计通过分别记录。
