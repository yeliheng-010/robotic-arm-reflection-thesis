版本：2026-10-28。论文题目：《基于机械臂的错误反馈于智能反思系统》。

本页为当前研究设计。早期“先扩到固定数据量再训练”的计划已被机制诊断优先的路线取代；历史方案见 [4113c24 版本](https://github.com/yeliheng-010/robotic-arm-reflection-thesis/blob/4113c24/docs/EXPERIMENT_PLAN.md)。本页不改写已完成实验协议；后续策略改动应另建冻结版本。

## 1. 研究问题与对应实验

| 问题 | 对照设计 | 当前证据 |
|---|---|---|
| 结构化反馈能否帮助失败恢复 | 同场景、同预算的重试/规则/模型闭环 | 早期 pilot 与后续规则/模型对照已完成；仍需独立覆盖 |
| 微调增加了什么 | 同基础权重、同输入/解码，禁用或切换 adapter | 60 条件：base55、两个SFT56、rule57 |
| 聚合是否提高抗噪能力 | 最新值/中位数 × 规则/基础模型 | 24 条件，三次预算下22→24；选择器结果相同 |
| 观测应在什么时候使用 | 固定首次/自适应规则/模型当前窗口/模型历史 | 24 条件，自适应17，其余14 |
| 模型为何不选择观测 | 固定原请求，改变动作表示/明确指令；独立费用探针 | 模型阶段已完成，见进度页 |

## 2. 比较时保持什么一致

- 冻结物体—目标组合、场景种子、故障条件、候选生成器、反馈可见范围和成功判据。
- 比较 adapter 时保持基础权重、量化、聊天模板和解码配置相同。
- 分开限制物理尝试次数与追加观测次数，同时报告实际使用量。
- 保存原输出及实际生效动作，非法输出进入失败分母，不用规则静默补答。
- 不向模型泄露故障注入真值、噪声真值、未来结果或评估答案；理想错误类型/阶段的假设另行声明。
- 阶段性修复不得追写已经冻结的结果。失败原版保留，新版记录修改与继承关系。
- 训练、开发、最终测试按任务身份和种子组隔离；同源快照不是独立新样本。

## 3. 最新已完成观测决策诊断的冻结设计

来源：已完成四组实验中的全部 82 个模型请求，以及 base_current 中“目标质量字段缺测且还有观测预算”的全部 11 个快照，涉及 10 条件、5 种子组。5 个发生于第一次失败，6 个发生于第二次失败，均余 2 次观测。不只挑三个获益案例。

### 模型部分

1. baseline：原始提示原样回放。
2. unified_first：在候选列表首位增加 OBSERVE 完整条目。
3. unified_last：将相同条目放末位，物理候选相对顺序不变。
4. missing_directive：在 unified_first 基础上加入明确观测指令。
5. 对 41 个 base_current 请求进行显式成本/许可读取探针。
6. 对 11 个快照的 0/1/2 次固定观测条件，分别请求基础模型选择一个物理动作。

合计 82×4 + 41 + 11×3 = 402 次任务请求，另有 2 次启动回放。温度0、seed42、max_tokens128、enable_thinking=false，使用基础4B且关闭adapter；超过输入上限拒绝，不静默截断。

82 条 baseline 要求精确复现原文本；不一致视为工程失败。明确指令组属于专家干预，不能当作模型自主发现策略。费用探针提供成本定义，只测显式读取。

### 物理部分

11 快照 × 3 观测水平 × 2 固定选择器（规则/基础4B），至多 66 个分支。共享默认观测和追加采样前缀，使用相同聚合和候选生成逻辑。

执行选择阶段只允许物理候选，保留真实剩余预算，并明示观测阶段已关闭。它与原自主观测策略有协议差异，不能直接当作原策略复测。

每个分支固定源失败快照和参数起点、按同场景种子重置、重试一次。不是恢复 MuJoCo 失败瞬间。主指标为下一次重试成功；不能和三次闭环成功率混用。

下图展示该冻结设计的已完成结果，各点分母均为11；不能据此声称自主观测策略已经有效。

![固定观测诊断的单次重试成功率](../assets/weekly_20261028/observation_value.png)

### 阶段门禁

单GPU模型 → CPU请求审计 → 释放模型资源 → 四GPU物理冒烟（4快照、24分支）→ 审计 → 剩余7快照、42分支 → 最终CPU审计。

工程门禁检查身份、调用、动作、物理记录与预算。不得因成功率低而修改门禁、换样本或丢弃结果。模型审计4项、物理审计12项篡改拒绝检查分别执行；实际通过状态以产物为准。

## 4. 统一报告的指标

| 类别 | 指标与分母 |
|---|---|
| 闭环效果 | 成功条件/全部条件、首次成功、初始失败后的恢复率 |
| 单次诊断 | 下一次重试成功/全部预定分支，单独报告无动作失败 |
| 决策 | 候选合法率、OBSERVE率、缺测时观测率、全量配对一致/不一致 |
| 成本 | 物理尝试、额外观测、任务模型调用、启动回放、token与模型时间 |
| 数据与训练 | 输入数、回复数、来源、有效更新、参数变化、重载一致性 |
| 稳定性 | 工程失败、跳过、中断、环境与代码身份 |
| 不确定性 | 按种子组和故障家族分层；后续独立评估再按实验单位报告区间 |

相关轨迹不冒充独立重复。当前24条件/6种子组和60条件/6批次内种子组的结果不作为统计显著性证据。不同研究中“预算曲线”是否为独立预算策略或同策略累计成功，必须按原协议区分。

## 5. 后续训练的启动条件

先获得可解释的失败机制和物理后果证据，再决定是否训练。候选标签应记录规则/教师/实验干预来源；缺测先观察的规则不能包装成模型自主推理标签。观测没有收益的样本和观察后仍失败的样本必须保留。

若启动新训练，先冻结数据与拆分，保持基础模型/提示/执行器不变；数据规模、监督目标和 epoch 分别控制。先小规模验证可学习性，再扩大独立条件，避免同时更改多个因素后无法解释结果。

最终盲测在策略和验收标准确定后运行，不用于循环选择最佳提示、训练轮次或模型版本。

## 6. 后续场景扩展：三个容器随机重新摆放（待执行）

**状态：仅登记设计，尚未实现、采样或运行。** 当前容器±1 cm是原位置附近的微扰，三个容器的整体布局仍基本固定；后续要改变的是放置目标的实际位置及相对布局。

- **随机对象**：BlueBin、RedBin、SortingTray分别采样桌面XY位置，允许改变彼此的相对方位，不仅共同平移。容器身份不随位置改变，例如RedBlock仍对应BlueBin。
- **范围与约束**：根据桌面边界、容器尺寸和机械臂可达性确定采样区域与最小间距，避免容器互相重叠、与物体/挡板穿透或超出台面；具体范围在实现预检后冻结，当前不预设未经验证的厘米数。首轮保持高度、朝向及其他因素不变。
- **对照顺序**：先比较原布局与仅容器随机布局，再分别叠加物体位姿扰动、反馈噪声/缺测，避免同时改变所有因素后无法归因。各方法使用相同场景与预算，目标坐标随场景更新；真实坐标用于仿真和验收，模型只接收协议允许的观测。
- **记录与展示**：逐任务保存种子、三个容器的初始/采样坐标、相对位移、布局校验结果和初始截图。后续用相同视角的原布局/随机布局对照，并标注容器位置，让变化可以直接看见。
- **预检与评估**：先检查场景加载、坐标是否实际生效、目标映射、可达性及无故障控制，再开展故障恢复对照。完整报告布局拒绝、控制失败、跳过及原因，不按某方法的成功与否筛选场景；训练/开发/测试按布局与种子隔离。

验收要求：三个容器均参与随机采样，实际坐标与截图对应，存在相对布局变化，约束和目标映射检查通过。该项使用新实验版本，保留现有数据与结果，不把当前截图当作随机重排已完成的证据。
