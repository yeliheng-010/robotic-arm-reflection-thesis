# 反思证据与教师输出改进计划

目标：改善错误反馈的可诊断性，并以冻结的验证任务检查教师修正能否带来真实物理恢复。

执行方式：当前会话串行执行，采用轻量 planning、TDD 和实际物理验收。原研究协议与数据保持冻结；新增模块仅位于独立 `improvement_20261019/code/training/refine`，本地保留同名模块。原有超长核心文件不做无关重构。

## 设计与边界

- `instrumentation.py`：在独立、单线程仿真工作进程中临时观察候选过滤、轨迹插值和碰撞；原检测与轨迹函数的参数、返回值和异常保持不变，结束后恢复函数。
- `engine.py`：继承现有 FeedbackEngine，仅向错误报告增加诊断证据，并保存每次尝试的诊断快照。不得读取注入故障标签来生成教师证据。
- `prompt.py`：明确可控参数、只读测量、单位、绝对值和历史失败。只接受模型生成的 cause/changes，不自动填修正值、不回退为规则。
- 先在六个训练任务检查输出；冻结候选提示词和代码后，在 seed=2001 的六个对应验证任务运行同预算物理比较。该验证种子上一轮已用于审计，不是全新独立测试集。
- 上游无候选保留为失败并单列；不放宽碰撞阈值、不凭模型文字断言安全。
- 测试集不参与开发、选方案或调参。通过验证仅允许进入补采决策，不等同于正式训练成功。
