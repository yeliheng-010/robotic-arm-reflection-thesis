# 测量驱动候选与模型选择实施计划

目标：在不改变物理执行器、过滤阈值或旧数据的前提下，减少碰撞/放置的参数选择和数值方向错误。

架构：只读复用上一轮冻结代码，新模块置于服务器 `decision_20261019/decision`，通过PYTHONPATH加载。程序根据观测残差/接触包围盒计算候选绝对参数，模型只选择候选；来源严格标记 `hybrid_llm_selector`。这是混合策略实验，不是纯LLM教师数据，不导出到原训练池。

执行：使用executing-plans在当前会话串行整合；独立仿真进程可并行，避免进程内遥测冲突。无Git操作、依赖修改、模型下载、正式训练或上游候选生成改动。

## 假设与约束

- 已定位：纯模型在碰撞时选择不改变路径的减速、在放置时改抓取点；同时存在偏移符号错误。
- 候选计算不接收隐藏故障标签。校准/放置对齐使用当前偏移减测量残差；越障使用接触障碍顶面减被搬物底面，加0.05m余量，得到抬升增量。越界时拒绝候选，绝不静默裁剪。
- 候选列表明确参数作用、无法保证的效果；选择失败/拒答不回退到规则。全部请求、选择、候选与最终Reflection保留。
- 同模型/解码的上一轮纯模型，以及独立RuleReflector作为对照；若混合不优于规则，不能声称模型选择有额外价值。
- 训练开发仅使用旧train的16/24/32/136/144/152。旧validation seed2001只能作回归；新seed3100的六项同族场景在冻结后才执行，仍不等于跨场景族泛化。原test保持冻结。

## 文件与验证

- `candidates.py`：只读测量→合法候选；测试非零当前参数、符号、越界、缺证据、无候选、输入不变。
- `selector.py`：中性候选说明、严格模型选择解析、来源标识、HTTP调用和审计记录；测试拒绝编造ID/参数、重复字段及拒答。
- `develop.py`：训练输入比较；真实生成全部留存。
- `experiment.py`：独立进程中的物理运行与冻结指纹，任务结束写结果和进度；校验组间首次物理条件。
- `verify.py`：候选重算、模型选择与执行匹配、预算/来源/旧哈希检查。
