# 三批数据审核与微调准备

目标：复核原始物理/模型记录，生成来源可追踪、按种子隔离、去重后的候选选择监督数据，并分析第三批失败。用户已批准审核后再确定微调方案。

边界：只新增本目录及更新进度文档；不修改冻结代码、协议、结果、预算或划分，不重跑物理实验，不启动模型服务和训练。审核为离线 CPU 作业。

设计：读取三批冻结协议并调用各批原有逐任务审计。只导出失败后紧邻一次物理成功的决策；模型输入使用原候选选择器的 messages 构造函数，hybrid 必须与实际请求完全一致，目标仅为 action_id。来源、场景、种子、原始文件及哈希保存在消息外的索引中，模板解释不得称为模型思维链。

第一批只用于 legacy_dev；第二、三批沿用 train_candidate / development_validation。以批次+种子为分组单位，验证同组不跨集合。去重使用规范化后的完整可见输入；同输入不同 action_id 全部隔离为歧义标签，不能当唯一正确标签。相同输入标签跨来源合并索引，并分别导出 rule/hybrid 子集。跨集合相同输入从训练中排除，开发诊断保留来源记录；不按数值近似删除不同物理状态。统计相关性组及精确重复，不把条目数当独立样本数。

风险：成功只证明该动作在该状态可执行，不证明唯一最优或反思有因果收益。候选未耗尽不证明存在可成功候选；对失败原因仅统计真实轨迹，不凭终态推断候选库上界。开发验证已用于开发，不是最终测试。
