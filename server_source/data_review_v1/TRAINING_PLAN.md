## 2. 一轮流程验证

从确认后的基础checkpoint新建独立adapter；不覆盖旧模型。先做1次真实梯度更新、保存、独立重载及输出检查，再冻结正式配置。建议初始LoRA rank8、学习率1e-4、有效batch8、seed42、1epoch作为待实测起点；训练精度、target modules、上下文上限由架构/显存预检决定，不预先宣称这些参数适配未知权重。

同一基础模型先保存49条开发诊断的生成结果；训练后用相同提示、候选和解码设置复测。记录实际样本覆盖、更新数、训练/验证loss、JSON合法率、候选合法率、单标签命中率、adapter参数变化及重载一致性。所有输出都按action_id解析；无非法响应兜底。

一个epoch是流程验证，不是最优轮次。只有开发结果改善且物理闭环不退化，才考虑2/3epoch，并保留各epoch独立结果。不得仅看低loss继续加轮数。

## 3. 物理闭环验收

沿用第二批20个、第三批40个开发条件，共60个条件；资格失败仍按原规则显式保留/跳过。比较规则、未微调与微调模型；两模型必须相同基础权重、量化和加载路径，仅切换adapter。当前Flash别名如与学生模型不同，只能另列教师基线，不能作同模型前后效果比较。

预算固定每任务最多3次尝试，同初态、同噪声、同候选生成器；不得为提高分数给微调模型更多重试。报告全部条件/实际执行/首次成功/恢复成功/服务故障、平均尝试、模型调用及延迟。对已观察到多个成功动作的输入，标签精确匹配只作辅助，以物理验收为主要指标。预留最终测试继续封存。

## 4. 针对性补采优先级

优先训练种子中的抓取+碰撞和抓取+放置失败，暂不再重复采集大量已接近全成功的单因素场景。当前保守训练中这两类仅11和21条，可能不足以学习多步恢复。

先离线挑选训练条件中的共同失败轨迹，明确“选择器选错”与“现有候选/三次预算不足”两个待验证假设。下一批独立预登记小规模候选对照：同一物理状态测试不同已有候选，完整保留成功和失败结果，并将额外候选探索预算与原三次闭环预算分开报告。未做该对照前，不把失败宣称为候选库问题或承诺微调能解决。

77组多成功标签先保留作独立歧义分析；如果将来要训练多有效动作目标，应另建版本，按同物理状态证据确定有效动作集合，而非把不同隐藏状态下的成功动作简单求并集后当通用真值。
