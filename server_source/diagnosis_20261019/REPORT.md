# 机械臂反思系统：失败归因与对照诊断

本轮范围是找出夜间持续故障低恢复率的原因，验证现有场景是否具备恢复路径，并明确正式采集、训练的前置条件。原始采集、模型权重和项目实现保持不变。

结论：本轮六个持续故障诊断任务中，历史教师和直接重试均为 0/6，规则反思为 5/6；剩余一个在抓取候选过滤阶段被阻塞。主要问题是教师修正质量和上游抓取适用范围，当前不具备直接扩大正式训练的依据。这是选定训练任务上的机制诊断，不是独立测试集上的方法效果结论。

## 数据与检查边界

- 审计夜间批次的 420 条训练、验证轨迹，另外比较旧 pilot 的 60 条轨迹。
- 未读取冻结测试轨迹来诊断或调参；最终只对原始数据集文件计算完整性哈希。
- 夜间冻结代码的全部登记 SHA256 与现有文件一致。
- 对照使用原始代码、相同对象/目标/种子/位置扰动和最多三次尝试。历史教师结果来自夜间已保存轨迹；本轮新运行直接重试和规则反思。
- 规则输出明确标记为 `rule`，不进入 LLM 训练样本池。

## 已定位的问题

### 1. 成功筛选不能保证修正答案正确

planning/grounding 注入只在第一次发生；simulation 路径每次都重新产生标准计划和真实定位，未根据 `replan/reground` 决定是否修复。任务 00000 中，教师将规划序列错误解释为抓取偏移，修改 `grasp_offset` 后第二次也成功。这种成功不能证明该答案正确。

本轮对任务 00000、00008 的直接重试均在第二次成功。因此这类样本当前只适合机制审计，不能作为“模型正确诊断并恢复”的主要训练证据。

代码依据：冻结快照 `reflection/fault_injection.py` 的 `corrupt_plan`；`reflection/engine.py:92` 的 simulation 规划路径、`:169` 的 grounding 注入、`:301` 的重试循环。

### 2. 校准：模型忽视轴向残差，还会输出无法执行的字段

校准任务有 42 次非法反思，其中 41 次为不允许的 `closure` 字段。执行器在非法反思时结束当前任务，因此即使尝试上限为三次，也可能提前停止。

任务 00016 的抓取残差约为 X=-5.18mm、Y=-42.13mm。教师第一次返回全部默认参数，没有修正偏移，随后仍空抓。57/84 项校准任务首次空抓，另有 24 项在候选阶段失败。不能只通过提高模型训练步数解决这些不同来源的失败。

代码依据：`reflection/reflector.py:24` 的参数校验；`reflection/engine.py:195` 的偏移应用、`:319` 的反思及非法输出处理。

### 3. 碰撞：教师通常修改了不相关的偏移参数

38 项首次发生碰撞的任务均未恢复。在碰撞错误对应的 73 次合法反思中，仅 3 次提高抬升高度，52 次修改抓取偏移。

任务 00024 已报告物体与 `SafetyDivider` 接触，教师仍把约 -5mm 的 X 抓取残差当成主要原因，把抓取偏移设为 -5mm，随后残差增加到约 -10mm，仍与隔板碰撞。本轮规则对照在相同任务中提高抬升高度后成功。

这说明至少该场景有可执行的恢复路径；不能将其归因为机械臂必然不可达，也不能推广为所有碰撞都可通过同一个高度恢复。

### 4. 放置：方向错误与重复无效修正

针对 `object_outside_container` 的 89 次合法反思都改了 `place_offset`，其中 81 次参数变化与残差同向或为零，只有 8 次方向相反。

任务 00032 的物体已经偏向目标负 X 方向，教师却继续设置负 X 偏移，之后出现与托盘碰撞。这里的方向检查按“新偏移减旧偏移”计算；不能把绝对参数误当增量，也不能把线性方向检查等同于物理成功证明。

代码依据：`reflection/monitors.py` 中 `placement_residual_xy` 的定义；`reflection/engine.py:226` 将故障偏差与修正偏移共同加到目标位置。

### 5. 几何抓取存在上游阻塞，现有修正参数无法作用到该阶段

训练、验证部分的橙球共 105 项，全部失败。16 个场景诊断覆盖四种物体、两个种子和有/无碰撞注入。

- 橙球在种子 2000、2001 下，即使无故障也触发场景碰撞过滤。全局碰撞占据比约 0.01546、0.01558，超过现有阈值 0.01；空抓判定为 false。
- 只保留目标点云作定位诊断时不触发碰撞过滤，说明场景其他点参与了候选排除。这不证明应该关闭碰撞过滤或忽略环境障碍。
- 圆柱在种子 2000、collision 条件下同样被过滤，指标约 0.01169；无故障时约 0.00390，可通过过滤。
- geometric 后端只生成一个候选，`candidate_index` 最终被截到 0。`grasp_offset` 在候选筛选之后才应用；当候选已被全部剔除时，这些修正都无法解决上游问题。

代码依据：`grasp_process.py:271` 只生成一个几何候选，`:331` 执行碰撞过滤；`reflection/engine.py:188` 获取候选，`:192` 截断候选索引，`:195` 才应用抓取偏移。

## 固定输入的新旧提示词对照

使用同一冻结 Qwen2.5-7B、相同 NF4/FP16 设置、贪心生成和最多 256 个输出 token，选取六个训练输入，共生成 12 个回答。

- 00024 碰撞：v1 输出 `lift_height=0.38`，v2 输出 `grasp_offset=[-0.005,0,0]`。输入、模型和解码设置固定，提示词确实改变了修正方向。
- 00016 校准：v1 输出非法 `closure`，v2 返回默认参数，二者均不能据此认定有效。
- 00136 校准：两个版本都输出非法 `closure`。
- 00032、00152 放置：旧版也存在选错参数或偏移符号错误，新版还出现非法 `placement_residual_xy` 字段。

因此不能直接把整个夜间批次的下降都归于提示词，也不能宣称恢复 v1 即完成修复。旧 pilot 与夜间批次还存在种子、对象和指令差异。

## 后续工作的验收顺序

1. 先建立无故障可执行性和故障实际触发检查。将无候选、未触发故障、执行后失败分别计数，禁止把这些混成一个恢复率。
2. 为候选过滤、碰撞和 IK 失败补充可观测的具体阶段和几何证据；保留安全过滤。候选多样化或执行前偏移的调整应在新代码快照中验证。
3. 提高教师结构输出和数值推理质量。以训练任务开发，在验证任务比较；不把规则答案改标为模型答案。校准、放置的轴向修正与碰撞的运动参数选择都必须经物理执行确认。
4. planning/grounding 若要支持因果恢复研究，需要定义真实持续错误与重规划/重定位的作用机制，冻结新协议后重新采集；旧数据保留原始身份。
5. 教师在持续故障上稳定优于同预算重试后，再补采并训练。现有 100/16/6 数据集与单样本 8 步检查均不足以证明正式训练或效果改善。

本轮不修改上述研究机制，不放宽碰撞阈值，不重建原始数据集，不启动正式训练。
