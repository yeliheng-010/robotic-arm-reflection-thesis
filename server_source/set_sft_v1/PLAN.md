# 189输入多成功动作微调

用户已批准适配多成功动作训练/评估并启动下一轮4B微调。本轮从同一Qwen3.5-4B基础权重独立训练1epoch，保留candidate_sft_v2的159条版本作为对照，不继续叠加旧adapter，冒烟权重不用于正式训练。

数据：原159个单标签训练输入＋新30个成功集合输入＝189个逻辑输入、197个成功回复。7个多成功输入全部保留，15个未解决输入不进入正例训练。新来源为规则分支搜索，保留立即/延迟成功标签及6个新种子组。原数据与新增输入的精确开发交集已核验为0；不读取预留测试。

目标：每个回复只监督assistant后缀token，先对token取均值，再在同输入k个成功动作中取均值，最后对本批输入取均值。即每个输入总权重相同，每回复权重1/k；逐回复反传避免保留多条长序列计算图。有效batch8，189输入共24次更新（尾批5），每个输入1轮、197个回复各访问一次。

沿用rank8、lr1e-4、seed42、NF4双量化/FP16、梯度检查点、显式KV重复＋高效SDPA、assistant后缀logits、clip1、AMP初始scale32。原159版本按回复token数聚合batch，本轮按输入等权；数据、聚合目标和更新步数均有变化，不能将效果变化单独归因于新增数据或多标签目标。182输入单标签消融本轮不自动提交。

评估：从已审计历史成功记录构建开发成功集合55输入（其中6个多解）、旧场景63输入（其中34多解），不再排除已验证的多成功标签；保留原49/29单标签诊断子集口径。新30输入只作训练集诊断，不称验证集。基础4B、原159版本和新189版本使用相同prompt、贪心、128token预算、无thinking；输出仍只能是一个合法action_id，集合内任一动作命中计成功标签命中。该指标不是物理任务成功率。

验证：边界和loss/gradient等价测试；完整输入无截断、逐目标候选合法与token mask；冻结数据、模型、旧adapter和代码；最长输入及最多成功动作的GPU真实更新、独立进程重载；正式训练逐步更新覆盖审计；前后评估全索引覆盖、合法性与集合命中、旧49/29文本回放、训练后独立重载。原冻结目录均不修改。

资源：全部Slurm，单GPU训练；三张GPU分片进行基础/旧版评估，训练完成后运行新模型评估。每GPU作业申请24GiB主机内存，四卡合计96GiB低于节点120000MiB调度内存。不额外启动模型服务、不终止其他任务。
