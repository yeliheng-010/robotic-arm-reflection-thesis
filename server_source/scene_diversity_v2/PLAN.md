# 场景多样性第一阶段实施计划

> 使用 executing-plans 在当前会话串行实施；用户已批准上一轮方案。

目标：独立接入全局位置、物体 yaw、容器外观和真实相机随机化，完成静态预检与小规模物理资格实验。
架构：冻结配置 -> 编译场景 -> 同相机 RGB/深度/分割 -> 现有执行器 -> 独立结果账本。
技术：Python、NumPy、MuJoCo、现有 env_sim、Slurm。所有 GPU 作业通过 Slurm。

v2工程修复：v1静态检查采到分割/深度轮廓不一致像素，原视角最大误差44.3cm；仅用3×3腐蚀排除边界后为0.86mm。沿用执行器已有的边界处理约定，保留原RGB/深度/分割，未放宽6mm阈值。v1无物理执行；v2复用已预登记种子，不把它们算成新种子。

## 已核查约束

- 旧实验保持冻结；新代码和产物仅写 scene_diversity_v2。
- 现有放置验收不支持容器 yaw，第一阶段保持容器朝向；物体 yaw 可改变。
- 现有基线使用仿真真值辅助定位/分割，颜色只验证外观与语义一致性，不宣称视觉理解收益。
- 相机 XML 为 cam / 58 度；env.fovy 存在固定缓存，必须在 reset 后同步。
- 第一阶段固定质量、摩擦、尺寸、照明，无新增故障/噪声，无训练/模型调用。
- 不读取封存测试轨迹，不修改公共 API、根配置、依赖或旧验收判据。
