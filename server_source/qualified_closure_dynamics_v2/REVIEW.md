# 来源修复自审与证据边界

范围限定为来源分类、登记和入口前置验证。没有修改v1冻结源码、真实初态、控制器、碰撞阈值或旧claim；不授权新动力学。本轮为串行代码自审，不声称独立子代理评审。

## 已处理的来源缺口

- 按当前与基础解释器的sysconfig/site目录及解析路径区分依赖/项目/标准库；项目中单纯名为site-packages的目录不会自动豁免，符号链接越界拒绝。
- 实际导入源码、二进制扩展、存在的字节码缓存逐份SHA256；依赖绑定发行包名称、版本、安装位置和METADATA/RECORD。多个安装位置分别登记，避免按全局包名误认另一个安装。
- 无文件代理追溯实现类型/加载器或类方法源码；原生子模块追溯规范名称的扩展父模块及包装器_native扩展。
- Cython共享支持模块绑定已加载扩展中包含对应签名的候选二进制集合，并记录exact_producer_identified=false。这是保守来源集合，不声称定位唯一生成者。未知无文件模块仍拒绝。
- 旧清单漏登记的15份项目源码已与本地逐字节核对，使用reviewed_sources.json显式补登记；不修改这些源码、不自动接受其后出现的新项目文件，也不重写旧历史覆盖范围。

## 入口与验证

v2入口先核验独立授权与全部来源，在禁止构造/积分的上下文中加载真实入口依赖并检查，再创建新的独占claim。缺授权或前置检查失败不会消耗claim。v1的已消耗claim仍在原目录，不迁移或清除。

真实导入检查阻断mj_step/mj_step1/mj_step2、MjData、MjModel的XML/二进制构造以及MjSpec的加载/编译。运行时导入的闭合、初态与记录模块沿用v1冻结实现。检查不加载场景，不调用控制器或推理；导入torch等库不等于模型生成。

准备和独立核验均验证所有已登记文件哈希；实际加载的模块/文件必须是已登记集合的匹配子集，新增真实来源拒绝。标准库和解释器可执行文件独立绑定。元数据查询所触发的导入最多用三次只读收敛，不涉及场景实验。

## 保留的失败与限制

6834来源测试先红，6836首次真实导入因虚拟模块归属失败，6838原生模块回归先红，6840因旧项目来源漏项失败，6842补登记回归先红。所有日志和修复前源码保留。6837/6841只读清点，未消耗动力学预算。

最终通过以Slurm最终测试、真实导入准备及独立进程核验的记录为准。本轮验证的是导入阶段来源与门控，不是环境初始化、attach约束、MJB回放、闭合轨迹或完整抓放。未来延迟导入的新模块仍需登记；这里不声称绑定操作系统全部动态链接库或证明虚拟支持模块的唯一生成者。包安装RECORD只反映当前安装，不提供旧运行的历史哈希证明。
